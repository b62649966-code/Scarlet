SCARLET — GITHUB AUTO DEPLOY (FIREBASE HOSTING)

Target project/site: wgsplus
Live URL: https://wgsplus.web.app
Hosting public directory: public

IMPORTANT: This workflow is for Firebase Hosting only. It does not deploy Realtime Database Rules or Storage Rules. Do not add private service-account JSON files to this repository.

1) Create a GitHub repository on github.com. Use a name such as scarlet-site. Choose Private if you do not want the source code public. Do not initialize it with a README, .gitignore, or license because this folder already has files.

2) Open PowerShell in this project folder (the folder containing firebase.json and .firebaserc). Check the target before proceeding:
   Get-Content .firebaserc
   Get-Content firebase.json
   The project must say wgsplus and the hosting site must say wgsplus.

3) Initialize Git and push the project. Replace OWNER and REPOSITORY with your GitHub username and repository name:
   git init
   git branch -M main
   git add .
   git commit -m "Initial Scarlet website"
   git remote add origin https://github.com/OWNER/REPOSITORY.git
   git push -u origin main

4) Set up Firebase's official GitHub integration from this same project folder:
   firebase use wgsplus
   firebase init hosting:github
   When prompted, enter OWNER/REPOSITORY. Allow the Firebase CLI to create the deploy service account, add the encrypted GitHub repository secret, and generate the GitHub Actions workflow. Choose the live deploy workflow for the main branch.

5) Commit and push the workflow files that Firebase created:
   git add .github/workflows
   git commit -m "Add Firebase Hosting auto deploy"
   git push

6) After that, each push to main automatically deploys to https://wgsplus.web.app. Check the repository's Actions tab for success/failure.

SAFEGUARDS:
- Do not run this from 77project or UltimateGameStash.
- Never paste a service-account JSON key into chat or commit it to Git. Firebase CLI stores it as a GitHub secret.
- Keep .firebaserc in the repository; it identifies wgsplus.
- If Git says the remote already exists, inspect it with `git remote -v` before changing it.
- If `git push` asks for sign-in, complete GitHub's browser authentication prompt.
